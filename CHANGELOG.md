### Fixed

- Fixed web AI chat auto-scroll fighting user scroll during AI thinking/streaming and clipping behind the bottom composer: replaced unconditional `scrollIntoView({ block: 'end' })` with `useChatAutoScroll` (`scrollTop = scrollHeight` inside `.chat-page__messages-body` to preserve the 180px composer clearance, immediately pausing auto-scroll when the user scrolls up, and maintaining reading anchor when loading older messages); also shortened `ChatHistoryPopover` (`max-height: clamp(240px, calc(100vh - 304px), 380px)`) and raised its `z-index` (`35` > composer `30`) so it never gets obscured by the composer's bottom gradient fade.
- Fixed intermittent `PROVIDER_TIMEOUT` ("Dịch vụ AI phản hồi quá chậm") errors in `ai-service` during multi-document RAG answers: raised `hive_read_idle_timeout_seconds` default/cap from `5s` (`le=5`) to `20s` (`le=30`) and Hive HTTPX connect/write timeout cap from `5s` to `10s`, increased Gemini `CHAT` per-attempt timeout from `30s` to configurable `60s` (`GEMINI_CHAT_ATTEMPT_TIMEOUT_SECONDS`, bounded by Core deadline), and expanded Hive fallback key routing from 1 key to up to 2 keys (`HIVE_API_KEY`, `HIVE_API_KEY_2`).
- Fixed web AI chat progress & error UX: moved pipeline progress into a quiet, collapsible inline chip on the `UniChat AI` header row (taking zero extra vertical height by default and displaying the live step title inside the thinking indicator), and moved recoverable request error cards from the top of the message list down to the bottom reply position directly underneath the failed question with auto-scroll and retry.
- Fixed web sidebar layout collapse (`flex-shrink: 0` on nav items, hidden scrollbars on 68px rail, slim translucent scrollbar when expanded, ellipsis truncation on long group names) and nested-route active highlighting (`/feed/posts/*`).
- Fixed two navigation/authorization flaws: removed hardcoded email/display-name `isAdmin` checks in `SideNavBar` in favor of authoritative `systemRole === 'ADMIN' && status === 'ACTIVE'`, and stopped coercing non-member public workspace previews (`userRole === null`) to `VIEWER` in `WorkspaceShell` so unjoined guests are not inserted into "Nhóm của bạn" and receive a "Tham gia nhóm" action instead of broken AI Assistant links.
- When the assistant cannot answer an `@AI` mention, the comment thread now says why (for example the AI provider is overloaded or unconfigured, or the asker already has two questions running) instead of one fixed sentence. The web shows the notice the server posted; the server maps the chat operation's error code to a Vietnamese reason and names an unknown code as is.
- Invite links opened by someone not signed in showed "Lời mời không dùng được — Phiên đã thay đổi" on the deployed site, although the link was valid. The preview request was tied to the session generation, and the failed session restore of a signed-out visitor bumped that generation while the preview was in flight, so the answer was thrown away. The preview now uses a public, session-independent request (`fetchPublicJson`). The page calls a link dead only when the server answers 404; any other failure shows "Chưa tải được lời mời" with a retry button.
- `@AI` in a comment now gets an answer. It used to fail every time: the old `AiRetrievalClient` path sent a deprecated service token that the AI Service rejected with 401, and its request lacked the policy fields the AI Service requires. Mentions now run through the same chat operation as the Trợ lý AI (session, membership and cloud-AI policy re-checked before every model call, rate limit and admission applied), and the answer is posted only if the post, the asking comment and the asker's membership are still there. Each mention also appears in the asker's own Trợ lý AI history. See ADR-0007.
- On web in development (React StrictMode), the wait for the assistant's answer stopped after the first check and reported "Trợ lý chưa trả lời" even when the answer arrived. Comments on feed cards now show that message too instead of hiding it. Web and mobile now wait up to 240 s, matching the server's deadline.
- Attachment summaries work again, now on request. They used to be produced automatically after a document was processed, through the same rejected service token as `@AI`, so every attachment ended at "Chưa tạo được tóm tắt". A member now presses "Tóm tắt bằng AI" on a document attached to a post ("Thử tóm tắt lại" after a failed attempt). The summary is produced from that document alone, as the member's own Trợ lý AI request, and is then shown to every member. - Comment avatars now show the author's uploaded picture, or their initial on the colour they chose. `GET /workspaces/{id}/discussions/{id}/replies` and the reply returned by `POST …/replies` carry two new fields, `authorHasAvatar` and `authorAvatarColor` (`authorAvatar` stays and is always null). ### Fixed

The `DocumentItem` type declared that phantom value too, and a test fixture had encoded it; both now carry the seven statuses the server actually sends. Correcting the type is what surfaced both call sites.
- Choosing a letter-avatar colour could never be stored: JPA wrote the enum's own name (`NAVY`) while `chk_users_avatar_color` from migration V24 admits only the lowercase keys, so every attempt failed the check constraint and the avatars fell back to the colour derived from the name everywhere. The column mapping now writes the form the column accepts; no migration and no data to rewrite, because the constraint had refused every uppercase value. Nothing in the test suite had covered the path.

One of them, `isBookmarked`, is read by the post detail page's "Lưu" button, which therefore cannot reflect the real state; the field is now typed as optional so the gap is visible rather than implied.

### Added

Everyone added must be someone you could already message one-to-one, so a group cannot become a way around that rule. Read state became a per-person watermark, so a
  conversation reports an unread count rather than a flag on each message (ADR-023).

Images render inline in the bubble; everything else is a download. Chat files stay private to the conversation and never enter a workspace's document library (ADR-022).

- Added lossless, locator-homogeneous text chunks with versioned metadata and heading-aware embeddings that keep cited source text unchanged.
